# 提醒规则说明

四条规则，从报表里筛出要提醒的订单，一轮汇总成一条消息发到飞书群。

## 用到的字段

订单号、离厂时间(承运商提货时间)、WMS过账时间、状态、合同状态、总箱数、
实际到达时间、签收时间、是否延迟、延迟原因。

「状态」里 `运输在途` 和 `运输在途（已离厂）` 是同一个业务状态，判定时都算在途。
时间一律北京时间。

## R1 WMS过账超时未离厂

| 项 | 内容 |
|---|---|
| 筛选字段 | 离厂时间(承运商提货时间)、WMS过账时间 |
| 条件 | 离厂时间为空 **且** WMS过账时间不为空 **且** 当前时间 − WMS过账时间 > 90 分钟 |
| 阈值 | 90 分钟，可配置 |
| 消息内容 | 订单数；每单：订单号、总箱数、已超时多少分钟 |

## R2 今日实际到达

| 项 | 内容 |
|---|---|
| 筛选字段 | 实际到达时间、状态 |
| 条件 | 实际到达时间的**日期**等于今天 **且** 状态为在途 |
| 消息内容 | 订单数、箱数合计；每单：订单号、总箱数 |

## R3 合同签署异常

共同前提：实际到达时间和签收时间都不为空，**且两者完全相等**
（说明签收时间是系统按到达时间自动带出来的，没有人真的做过签收动作）。

在此前提下分两种情况：

| 场景 | 条件 | 含义 |
|---|---|---|
| 客户未电子签 | 状态 = `已签收` 且 合同状态 = `签署中` | 客户没完成电子签 |
| 运营未操作签收 | 状态为在途 且 合同状态 = `已完成` | 运营没把状态更新成已签收 |

消息内容：两组分开列。客户未电子签组给订单数、箱数合计、每单订单号+箱数；
运营未操作签收组给订单数、订单号清单，并提示"请运营人员将状态更新为「已签收」，
合同状态为「已完成」"。

## R4 延迟无原因

| 项 | 内容 |
|---|---|
| 筛选字段 | 是否延迟、延迟原因 |
| 条件 | 是否延迟 = `是` **且** 延迟原因为空 / 空字符串 / 全是空格 |
| 消息内容 | 订单数、订单号清单 |

## 重复提醒规则

同一个问题不要每轮重发。判定"是不是同一个问题"的口径：

| 规则 | 同一个问题的判定 | 重复提醒 |
|---|---|---|
| R1 | 订单号 + WMS过账时间 | 发过就不再发。过账被撤销重做后时间变了，算新问题，重新发 |
| R2 | 订单号 + 日期 | 发过就不再发，跨天算新的 |
| R3 | 订单号 + 场景（两个场景各算各的） | 未解决的，每天 9 点后可再提醒一次 |
| R4 | 订单号 | 未解决的，每天 9 点后可再提醒一次 |

问题消失后又出现：只有安静满 12 小时再出现才算新问题、才重新提醒；
时间更短的（数据抖动导致这轮没命中、下轮又命中）不重复发。

判断"问题是否已解决"时，只看**本轮报表里出现过的订单**。报表按当月口径导出，
上个月的订单这个月不在报表里，不能因为"没看见"就当成已解决。

## 消息组织

一轮只发一条消息，按 R1 → R2 → R3 → R4 分段，段首标明规则。每段三种情况：

- 有新的要提醒：列明细；如果当前命中数多于本轮要发的数量，先说明
  "当前符合条件共 N 个订单，本轮新增 M 个，另有 K 个此前已提醒"。
- 当前有命中但本轮都提醒过了：说明"当前仍有 N 个符合条件订单，本轮无新增提醒"。
- 一个都没命中：写"无符合条件订单"。

消息开头 @ 指定负责人（未配置就发普通群消息）。
